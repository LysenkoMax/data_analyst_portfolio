# SQL Data Analytics: Анализ маркетплейса Olist (Бразилия)

В этом разделе представлены мои решения бизнес-задач для крупнейшего бразильского маркетплейса с использованием **SQL**. Проект охватывает анализ 100 000 заказов за 2016–2018 гг.

> **Цель проекта:** Трансформировать сырые данные о транзакциях в понятные инсайты для отделов логистики, маркетинга и клиентского сервиса.

---

## [Модуль 1: Логистика и клиентский опыт](logistics_analysis/README.md)

Исследование эффективности цепочки поставок и её прямого влияния на удовлетворенность покупателей.

*   **Среднее время доставки по регионам** 

    *Анализ показал штаты-аутсайдеры, где доставка занимает аномально много времени, что позволяет точечно оптимизировать логистику.*
*   **Процент задержек (OTD Analysis)**  
    *Расчет доли опозданий с фильтрацией через `HAVING` для отсечения штатов с низкой репрезентативностью данных.*
*   **Влияние логистики на NPS (Review Score)**  
    *Критический инсайт: средняя оценка заказа падает с **4.3** до **2.2**, если доставка произошла позже обещанного срока.*

## [Модуль 2: Экономика клиента (LTV & Retention)](customer_economics/README.md)

Анализ ценности клиентов и частоты их возвращения на платформу.

*   **LTV (Lifetime Value) по штатам**  
    *Использование `CTE` для расчета совокупного дохода от каждого уникального клиента (`customer_unique_id`) в разрезе географии.*
*   **Цикл повторных покупок (Window Functions)**  
    *С помощью функции `LEAD` рассчитано среднее количество дней между первой и второй покупкой для оценки лояльности аудитории.*

## Технический стек и навыки SQL

### **Продвинутый SQL**
- **Оконные функции:** `ROW_NUMBER`, `RANK`, `LEAD`, `LAG` (анализ последовательностей и ранжирование).
- **Сложные структуры:** Обобщенные табличные выражения (`CTE`), многоуровневые подзапросы.
- **Работа с датами:** Вычисление интервалов через `JULIANDAY`, форматирование `STRFTIME`.

### **Базовые операции**
- **Объединения:** `JOIN` (INNER, LEFT), `USING`, `UNION`.
- **Фильтрация и агрегация:** `GROUP BY`, `HAVING`, `SUM`, `AVG`, `COUNT`.
- **Трансформация данных:** Сложная логика в `CASE WHEN`, обработка пустых значений через `COALESCE` / `IFNULL`.
